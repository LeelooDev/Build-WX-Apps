# 微信小程序运行与调试

## 能力分工

- **编译 / 打开 / 截图 / 结构快照 / 点击输入 / 日志 / 报错映射** → wx-agent MCP 工具（下文按功能名引用，如 `wx_run`、`wx_screenshot`；会话里的实际名称可能带命名空间前缀，**按功能名从已加载工具列表匹配**）。
- **改代码** → 常规文件工具。

## 核心工作流

### 1) 先体检

`wx_doctor`。它一次性告诉你：开发者工具装没装、登录没登录、工程是什么类型、依赖全不全、产物编没编、sourcemap 有没有。

常见结论与对策：

- **"HBuilderX 模式，无法由命令行编译"** → 这个工程没有 npm 编译能力。转 `wx-uniapp-pitfalls` skill，用 `wx_init` 补齐（不改目录结构，HBuilderX 仍可用）。
- **"未登录"** → 让用户打开微信开发者工具扫码登录，这个你替他做不了。
- **"缺 node_modules"** → 在工程目录 npm install。

### 2) 跑起来

`wx_run`。一步完成"编译 → 在开发者工具里打开产物 → 建立自动化连接"。

- 产物已是最新会自动跳过编译；改了源码想强制重编用 `rebuild: true`。
- 边改边调用 `watch: true`，改源码后开发者工具会自动重新加载。

**如果失败**：

- 编译错误 → 用 `wx_compile` 拿结构化错误（已按根因去重）。别去翻原始 webpack 输出。
- 自动化端口连不上 → 让用户确认 **开发者工具 → 设置 → 安全设置 → 服务端口（CLI/HTTP 调用）已开启**。这是硬前提，关着的话什么都连不上。

### 3) 确认真的渲染出来了

**`wx_run` 返回成功不等于界面正常。** 必须 `wx_screenshot` 看一眼。白屏、卡在启动页、报错遮罩，都只有看图才知道。

### 4) 查报错

**优先 `wx_errors`，不要先用 `wx_logs`。**

`wx_errors` 会把运行时堆栈用 sourcemap 映射回原始 `.vue` / `.js` 源码，直接给出文件名、行号和出错处的代码片段：

```
[1] unhandledRejection · _this.someMethod is not a function
    → pages/demo/form.vue:97:0
        95 | 			async onSubmit() {
        96 | 				this.someMethod();
    >   97 | 				if (!this.account) {
```

注意：`async` 函数经 babel 转译后行号可能有 ±1 偏移，所以上下文代码片段比行号本身更可信，**以片段里那行实际代码为准**。

`wx_logs` 用于看正常的 console 输出（请求返回了什么、状态流转到哪一步）。

### 5) 日志的时间窗口

**日志只从建立连接那一刻起才开始收集。** 所以顺序必须是：先 `wx_run`（或任意一次连接）→ 再触发行为 → 然后 `wx_logs`。

如果先操作再连接，那段日志永远拿不回来。要复现就重新走一遍。

## 改完代码之后

1. 改源码
2. `wx_compile`（或 watch 模式下等它自动重编）
3. **重新连接一次**——重新编译会让注入的错误钩子失效，不重连就抓不到新报错
4. `wx_screenshot` 确认效果

## 排查手段

- **看状态而不是看界面**：`wx_page_data` 直接读页面 `data`，比对着截图猜状态可靠得多。
- **跳过前置流程**：`wx_call_method` 直接调页面方法（如 `onSubmit`），比模拟一串点击稳。
- **跳到指定页面**：`wx_navigate`，不用一路点过去。tabBar 页面必须用 `switchTab`。
- **任意求值**：`wx_eval`，例如 `return getCurrentPages().map(p => p.route)`。
- **隔离后端依赖**：`wx_mock_wx_method` 打桩 `wx.request` 等，排除网络因素。

## 多步流程与时序问题

单张截图看不出"点了没反应""动画卡在中间""先后顺序错了"。这类问题用 `wx_record` 连拍：它按固定间隔连续截图并合成 GIF，GIF 给用户回放，你自己读关键帧图片。
